## Integration repairs

1. **Duplicate `RRFc` token** (system + decimal files defined it identically).
   Removed the token and both `attach` blocks from `s390x_decimal.sinc`;
   decimal reuses the system definition. Static scan confirms no remaining
   duplicate token/field/macro/register definitions.
2. **`RILa_I2` signedness syntax**: `signed` must come *after* the bit range
   (`RILa_I2 = (0,31) signed`), not before. Prefix placement was silently
   ignored, so MSFI/MSGFI displayed `0xffffffff` instead of `-0x1`.
   Fixed in `s390x.slaspec`, rebuilt, verified (`MSGFI r9, -0x1`).
3. **Harness — decimal SS structural comparison** (`tests/sleigh_diff.py`):
   zero⟺omitted. Covers ap/sp/mp/dp/cp/zap/pack/unpk/mvo/pka/pku/tr/trt/
   trtr/mvn/mvz/unpka/ed/edmk/srp/tp.
4. **Harness — 20-bit displacement reconstruction**: our RXY/RSY displays
   follow the core convention of printing only the low 12 bits (DL2);
   Capstone prints the full signed 20-bit displacement. For RXY-form
   mul/div (`dl,dlg,dsg,dsgf,mfy,mg,ml,mlg,msy`) and `clclu`, the harness
   reconstructs `(DH2<<12)|DL2` sign-extended from the encoding bytes.
   P-code was already correct (`ea_D20`); this is display-only.
5. Pre-existing harness normalizations kept: PC-relative targets
   (BRCT/BRCTG/BRXH/BRXLE/BRXHG/BRXLG), short-FP `fNh`→`fN` aliases,
   even-R1 pair literals→register names, BCR extended mnemonics,
   BRCL `jg*` spellings, SS length L+1 (mvc/xc/nc/oc/clc), LM/STM R1/R3.
6. **Harness — STMY R1/R3 literals** (`tests/sleigh_diff.py`): the 256
   generated STMY constructors print R1/R3 as plain numbers (like
   gen_lmstm.py); added `stmy` to the LM/STM tuple so the harness maps
   them back to r-names for comparison.

### Honest p-code limitations (documented in-spec)

- **BFP→fixed / HFP→fixed**: Decode-only. SLEIGH p-code has no
  float-to-integer conversion operator (only INT2FLOAT exists); the rounded
  result cannot be materialized as an integer honestly.
- **TEST DATA CLASS (TCEB/TCDB/TCXB)**: Decode-only. Full bit-manipulation
  p-code was attempted but hit unresolvable SLEIGH size-restriction errors
  on the And operator with constants in this context.
- **Extended 128-bit**: LXEBR/LXDBR model only the high 64 bits (documented).
  MAYL/MYL decode-only (low product half not in modeled state).
- **DIEBR/DIDBR**: Decode-only (iterative quotient/remainder not representable).
- **HFP**: Uses IEEE FLOAT_* approximations as documented (user-approved).
- **DFP**: Tokens defined in-spec (DFPab, DFPd, DFPe_*), but decode-only
  constructors not added in this phase. DFP opcode mapping (0xB3xx/0xEDxx)
  requires careful PoP verification; Capstone 5.0.7 DFP support was probed
  but mnemonic mapping was inconsistent. Recommended for follow-up phase.

## September 21, 2026 — eight-workstream integration batch

Eight parallel workstreams (conditional-BCR p-code, April-2025 PoP audit,
BSM/BASSM/LAE/TRACE/LAM/STAM, old/extended HFP, ELF relocations, z/OS
loaders, vector semantics/divide exceptions, XPLINK/BRCT/coverage) were
integrated, then the tree was audited again during final validation.
The audit found and fixed three real defects in the signed-divide path:

1. **`sdiv64_exc` trapped `INT64_MIN / 1`.** Per PoP the exception fires
   only when the quotient cannot be expressed as a 64-bit signed integer;
   `INT64_MIN / 1 = INT64_MIN` is representable. The erroneous `dvs == 1`
   trap was removed; only `INT64_MIN / -1` traps.
2. **Unsigned `/` and `%` used for signed division.** In SLEIGH, `/`
   compiles to `CPUI_INT_DIV` (unsigned) and `%` to `CPUI_INT_REM`
   (unsigned); signed division needs `s/` (`CPUI_INT_SDIV`) and `s%`
   (`CPUI_INT_SREM`). Both `sdiv32_exc` and `sdiv64_exc` used the unsigned
   operators, producing wrong quotients/remainders for negative operands
   and spurious quotient-overflow traps. Fixed to `s/`/`s%`.
3. **32-bit quotient-overflow check missed quotients ≥ 2³².** The check
   `sx32(qf,qf); if (qf != q)` relied on the `(x ^ 0x80000000) -
   0x80000000` trick, which passes bits 32+ through unchanged — so e.g.
   `2³² / 1` round-tripped and failed to trap. Fixed by masking
   `qf = q & 0xffffffff` before the sign-extension round-trip.

Also fixed: stale `gen_muldiv.py` comments claiming unsigned divide
exceptions are unmodeled (they are modeled via `udiv64`/`udiv128`).

**Validation added:** `tests/validate_div.py` — 20 edge vectors (D/DR,
DSGR/DSG/DSGFR, DLR/DLGR unsigned paths, zero divisor, signed quotient
overflow, `INT64_MIN / -1` vs `/ 1`, negative dividend/remainder sign,
destination preservation on traps): **20/20**. Plus 300 randomized DR
trials against Python big-int reference: **0 mismatches**.

### TRTT correction (same batch)

The tree briefly carried a bogus SS-format TRTT at opcode `0xD9`;
`d92010002000` decodes as MVCK, so `0xD9` is not TRTT. Removed and
replaced with the real RRF-c TRTT at **B990** (M3=0 only), modeled on the
TRTO/TROT/TROO pattern: 2-byte source characters, 2-byte table entries,
table index `2 * source_character`, test character from GR0 bits 48–63,
CC=1 on match (no store, no advance past it), CC=0 on exhaustion.
`tests/validate_trtt.py`: **6/6**. Approximations documented in-spec:
CC=3 partial completion runs to completion; nonzero M3, alignment,
facility-dependent and unpredictable-overlap behavior not modeled.

### TM16 condition-code fix (same batch)

`cc_tm16` (CC=0 zero, CC=3 all-ones, mixed CC=1/2 by field MSB).
